On shadcn/ui

Short answer: take its token architecture, skip the library.

Skip the install

shadcn/ui requires Tailwind. You have 425 lines of hand-written global CSS across 135 semantic class names and no Tailwind anywhere. Adopting it means rewriting every className in 2,360 lines of TSX — a full rewrite billed as a redesign, on an app whose layout depends on subtle minmax(0, 1fr) grid work.

It won't help the canvas

Your hardest UI is a pan-zoom viewport, an SVG ink layer, Mermaid rendering, and a streaming transcript. No component library ships those. The parts shadcn is genuinely good at — dialog, popover, combobox — are maybe six of your surfaces.

Steal the tokens

shadcn's real idea is semantic CSS variables with a dark override block. That is plain CSS. Adopt the naming, keep your stylesheet, and dark mode falls out of it. This is the whole recommendation.

Radix, if anything

If you want the accessibility work on the project popover and the agent menu (which is a <details> today), install Radix primitives directly. They're unstyled and don't care that you use plain CSS. That's what shadcn wraps anyway.

And it decides the VR question

react-three-fiber renders to WebGL — no DOM, no classes, no CSS. Tailwind and shadcn contribute nothing there. A framework-neutral token module does: colors, spacing, and type scale that both the DOM shell and your r3f materials read from one source.

Where the tokens live

src/shared/design/tokens.ts — a side-effect-free object, which is exactly what src/shared is already specified to hold. CSS variables are generated from it; the VR client imports the same object.

The structural problem

The screenshots show it more clearly than the CSS does: every panel floats over the canvas instead of docking beside it. The drawing toolbar sits on top of the first participant boxes, the ask pill covers the bottom lifeline labels, the zoom controls land on the Provider column, and opening the conversation hides the right third of the diagram. Fit-to-view has no idea any of that chrome exists.

Panels take real columns and the canvas reflows, both rails resizable. Only the toolbar and zoom still float — and they publish their footprint as insets, so Fit never parks a node under a button.

Tokens

Chrome is strictly achromatic. Every hue in the app carries meaning: run state, mode escalation, git status, and diagram ink. The most colorful thing on screen is always your own drawing. Each swatch below shows light on the left, dark on the right.

--sheetDiagram surface
--shellInstrument ground
--inkPrimary text, buttons
--mutedLabels, metadata
--lineHairlines
--liveRun in progress
--waitAgent mode, approvals
--stopFailed, denied
--plotDiagram ink, links
--addAdditions
--delRemovals
--shell-sunkWells, inputs

Three typefaces, three jobs. Geist runs the interface at 12–15px. Geist Mono takes everything that is data rather than prose — paths, diffs, tool names, counts, zoom — which is close to half the text in the app. Archivo at expanded width appears only as a titleblock: the wordmark, the canvas name, and empty-state headlines. Never below 24px, never more than once per screen. All three load through next/font/google, which self-hosts at build time — a local-first app shouldn't need a CDN to render its own type.

How this lands

Four stories, in dependency order. Nothing here needs a new dependency except the fonts, and each step leaves the app shippable.

01 Tokenize the stylesheet 73 distinct hex values and 49 rgba() literals become ~30 semantic tokens. Mechanical, reviewable, and the app looks identical when it's done. This is the step that actually unblocks dark mode. no visual change
02 Add the theme switch Light / dark / system, stamped as data-theme on <html> by a small inline script in layout.tsx so there's no flash before paint. Mermaid is the catch: themeVariables is hardcoded light in mermaidRenderer.ts and caches after first init — it needs to read the computed tokens and re-render on change. dark mode ships
03 Dock the panels Overlays become grid columns, both rails resizable, floating chrome publishes insets that fit-to-view consumes. The largest change and the one users will feel first, because the diagram stops being covered up. largest diff
04 Restyle on the new tokens Typefaces, the 48px header with breadcrumbs, the run ribbon, mode escalation colour. Only at this point does anything look different, and by then it's a values change rather than a rewrite. the redesign

The order matters more than the palette. Steps 1 and 2 are worth doing even if you reject every aesthetic choice on this page — they're what turn "add dark mode" from a rewrite into a diff, and what gives the VR client something to read colours from.
